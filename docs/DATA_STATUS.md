# 법규 데이터 현황 (2026-11-06 기준)

검토 엔진은 **사람이 승인한 규칙만** 쓰고, 쉬운 설명은 **사람이 승인한 사실 원장**이 있을 때만 만듭니다. 아래는 저장소에 들어 있는 원문과 규칙이 어디서 왔고, 무엇이 아직 사람 확인을 기다리는지입니다.

`bootstrap --approve-as 이름 --ack-warnings --confirm-transcriptions` 는 **개발·시연용 일괄 승인**입니다 (규칙·원장 승인, 단서 경고 확인, 표 전사본 대조 확인을 그 이름으로 기록). `APP_ENV=prod` 에서는 거부됩니다.
운영 전에는 검수자가 관리자 API 로 하나씩 확인합니다: `GET /admin/rules?status=auto_checked` (또는 `draft`) → `GET /admin/rules/{id}` (원문 하이라이트·전사 메타·원장 초안) → `POST /admin/rules/{id}/approve` → `POST /admin/ledgers/{id}/approve`.

### 사람 확인이 필요한 것

- **주차장법 시행규칙 표 3개**(제3조① 주차단위구획 2개, 제6조①3나2) 차로 너비 1개)는 law.go.kr 에 이미지로만 있습니다. 원본 이미지를 보관하고(`raw/supp_*.gif`, sha256 기록) 칸 단위로 옮겨 적었으며, 전사자는 `claude-opus-5-5 (AI 이미지 판독)`, **대조자(verified_by)는 비어 있습니다.** 이 전사본을 근거로 한 주차구획·차로 폭 규칙은 검수자가 원본 이미지와 대조한 뒤 승인해야 합니다. (원본 이미지 자체에 '3.3.미터' 오기가 있어 그대로 옮겼습니다.)
- `v_text_match` 는 모든 버전이 `not_checked` 입니다. 국가법령정보 공동활용 Open API(OC 인증값 + 서버 IP 등록) 원문과 대조되지 않았습니다. OC 를 받으면 `python -m app.cli refresh-sources` 로 공식 XML 을 받아 같은 버전인지 확인하세요.

## 2. 규칙 (data/seed/extractions/)

`scripts/build_seed_extractions.py` (LLM 이 아닌 **규칙형 추출기**)가 위 원문에서 만든 규칙 추출 결과(rule_extraction@1.0)입니다. 실시간 LLM 추출(`python -m app.cli extract`)과 같은 기계 검증(인용문 원문 일치·숫자 일치·상위 범위·단서 경고)을 통과해야 저장됩니다.
현재 95개 규칙 모두 기계 검증을 통과했고, 그중 일부는 '같은 조에 단서·특례(다만/불구하고)가 있음' 경고가 붙어 있어 검수자가 해당 여부를 확인해야 합니다 (예: 조례 제80조 ②~⑨ 방재지구·정비사업 특례, 시행령 제84조 ④⑤).
용도 이름을 맞추지 못한 항목(예: 시행령 별표 5 파목 ↔ 조례 '동물 및 식물관련시설 중 …')은 '별도 확인 필요'로 남습니다.

| 카테고리 | 국가(L1) | 대구(L3) | 비고 |
| --- | --- | --- | --- |
| 건폐율 | 21개 용도지역 (시행령 제84조①) | 21개 (조례 제75조) | 조례 값은 승인 시 상위 범위 재검사 |
| 용적률 | 21개 (시행령 제85조①, 범위) | 21개 (조례 제80조①) | 준주거·계획관리는 단서('다만') → 조건부 검토 |
| 건축 가능 용도 | 제1·2·3종일반주거, 자연녹지 (별표 4·5·6·17) | 같은 4개 (조례 제33·34③·35·46조) | 상업·준주거·공업 등은 별표가 '건축할 수 없는 건축물' 목록이라 미수집 → 별도 확인 필요 |

## 3. 필지 데이터
