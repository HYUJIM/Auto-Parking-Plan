## 1. 작성 범위와 기존 대화의 반영

이전 대화에서는 프로젝트의 진행 수준을 **개발 참고용 법규 자료를 선별·분류하고 일부 JSON 형태로 정리한 단계**로 설명하였다. 이 문서도 그 취지에 맞춰 국가 법률, 하위 법령, 지자체 조례, 지역 특화 규제를 연결해 살펴보는 자료 체계를 정리한다.

이번에 불러온 이전 대화 기록에는 인포그래픽 원본 이미지, 전체 법령 목록, 기존 JSON 파일이 포함되어 있지 않았다. 따라서 아래 내용은 **확인 가능한 대화의 구성과 표현 방향을 반영하고 공식 출처로 보완한 재구성본**이다. 원본 인포그래픽의 모든 항목·문구·배치와 일치하는지, 기존 데이터가 실제로 어느 정도 구축되었는지는 대조하지 못했다.

| 구분 | 이 문서에 반영한 내용 | 확인 범위 |
| --- | --- | --- |
| 기존 대화에서 확인 | 국가 상위법, 하위 법령, 지자체 조례, 지역 특화 규제의 구분 | 문서 구성 방향 확인 |
| 기존 대화에서 확인 | 대구·경북 지역 구분, 주요 법령, JSON 예시, 파일 체계 | 포함해야 할 항목 확인 |
| 기존 대화에서 확인 | 완료된 시스템처럼 보이지 않는 표현, 오탈자와 깨진 문자 정리 | 표현 방향 확인 |
| 이번 작업에서 보완 | 아래의 구체적인 법령·조례 후보와 공식 출처 | 출처별로 확인 수준을 별도 표시 |
| 이번 작업에서 작성 | JSON 예시와 폴더·파일 체계 | 개발용 설명 예시. 기존 저장소를 확인한 결과가 아님 |

이 문서에서 말하는 정리는 자료를 검토하고 개발에 참고하기 위한 수준이다. 법규의 전수 수집, 자동 연계, 최신성 검증, 필지별 적용 판단 또는 서비스 구현이 완료되었다는 의미로 사용하지 않는다. 기존 요청을 반영해 별도의 향후 계획·확장 계획 항목은 두지 않았다.

## 2. 법규 자료의 계층과 연결 관계

### 2.1 자료를 찾는 기본 순서

1. 국가 법률에서 검토 주제와 기본 요건을 찾는다.
2. 해당 법률의 시행령·시행규칙과 별표를 연결한다.
3. 법령의 위임 대상과 토지 소재지를 확인해 지자체 조례·규칙을 연결한다.
4. 해당 필지의 구역 지정, 고시, 계획 및 도면을 별도로 대조한다.

헌법은 상위 규범이지만, 이 문서의 실무 자료 정리 범위는 토지 이용과 건축에 직접 관련된 법률 이하의 규정 및 개별 계획·고시를 중심으로 한다.

| 자료 구분 | 역할 | 정리할 정보 |
| --- | --- | --- |
| 국가 법률 | 토지 이용, 건축, 개발·보전의 기본 요건과 절차 | 정식 법령명, 조문, 적용 대상, 위임 규정 |
| 시행령 | 법률에서 위임한 구체적 범위·기준과 집행 사항 | 관련 법률 조문, 세부 요건, 별표, 예외 |
| 시행규칙 | 절차, 제출서류, 서식 등 세부 사항 | 관련 법률·시행령, 서식, 신청·신고 요건 |
| 지자체 조례·규칙 | 관할 사무와 법령의 위임 범위에 따른 지역 기준 | 제정 지자체, 적용 범위, 위임 근거, 별표 |
| 지정 고시·계획·도면 | 특정 구역의 경계와 계획 내용, 해당 위치의 세부 조건 | 고시번호, 지정·변경일, 계획 문서, 경계 도면 |

이 순서는 **자료 검토 순서**이며, 단순한 법적 우선순위표가 아니다. 법률에서 조례로 직접 위임하는 경우도 있으므로 모든 규정을 반드시 시행령·시행규칙을 거쳐 조례로 내려오는 직렬 구조로 처리하지 않는다. 조례 제정의 범위와 위임에 관해서는 [지방자치법 제28조](https://law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1000485630)를 참고한다.

특화구역은 조례보다 아래에 있는 별도의 법령 단계가 아니다. 해당 구역에 관한 법률·하위 법령, 지정 고시 및 계획을 일반 규제와 함께 검토하는 **중첩 조건**으로 관리한다. 규정 간 관계는 개별 위임 조항, 적용 대상, 특례, 예외 및 경과조치에 따라 확인한다.

### 2.2 초기검토용 분류 기준

| 분류 기준 | 주요 입력 항목 | 분류의 목적 |
| --- | --- | --- |
| 지역 | 시·도, 시·군·구, 소재지, 필지 식별정보 | 관할 법규와 계획 자료 선택 |
| 토지 상태 | 지목, 실제 이용 상태, 면적, 용도지역·지구·구역 | 추가 검토할 규정 후보 선별 |
| 예정 행위 | 건축, 용도변경, 토지 형질변경, 농지·산지전용 등 | 행위별 검토 항목 구분 |
| 예정 용도 | 주거, 근린생활시설, 창고, 공장 등 | 건축물 용도와 입지 조건 검토 |
| 지정·계획 | 특화구역, 산업단지, 지구단위계획 등 | 중첩 규제와 계획 확인 |
| 시간 | 검토 기준일, 공포일, 시행일, 적용 경과조치 | 적용할 자료 버전 구분 |

위 표는 데이터 설계용 분류 기준이다. 필터링 결과는 검토할 자료의 후보이며, 그 자체가 허가·불허 결론은 아니다.

## 4. 대구·경북 지자체 조례의 구분

### 4.1 관할별 연결 방식

| 지역 구분 | 조례 자료의 구성 | 정리 시 유의점 |
| --- | --- | --- |
| 대구광역시 | 광역시 도시계획·건축 조례와 해당 구·군의 관련 조례 | 광역 조례 하나로 적용 범위를 단정하지 않고, 개별 조례의 관할·위임 범위를 확인 |
| 경상북도 | 도 조례와 소재 시·군의 도시계획·건축 조례 | 경상북도 조례만으로 포항·구미 등 각 시·군의 세부 기준을 대체하지 않음 |
| 경제자유구역 등 | 소재 지자체 조례와 구역에 관한 별도 법령·계획 | 행정구역과 특화구역을 각각 기록하고 관할 기관을 별도로 확인 |

대구의 군 단위 조례가 존재하는 사례로 [대구광역시 군위군 건축 조례](https://www.law.go.kr/ordinInfoP.do?ordinId=2231757)를 확인할 수 있다. 도 조례와 시·군 조례의 관계는 각 조례의 적용 범위와 위임 근거에 따라 대조한다.

| [구미시 도시계획 조례](https://www.law.go.kr/LSW//ordinInfoP.do?chrClsCd=010202&gubun=ELIS&ordinSeq=2175525) | 2026-10-01 시행, 조례 제2122호 | 시 단위 조례와 버전 표제 확인 |

**시행 예정 자료의 처리:** 위 대구광역시 건축 조례 제6551호는 문서 기준일인 2026-11-05에 시행 중인 버전으로 사용하면 안 된다. 해당 날짜에 적용할 조문은 연혁과 부칙을 통해 별도로 확인해야 한다. 이 문서에서는 그 확인을 완료한 것으로 표시하지 않았다.

위 목록은 대구·경북 전체 자치법규의 수집 목록이 아니다. 실제 대상지의 조례를 추가할 때에는 시·도와 시·군·구, 조례명, 조문·별표, 시행일을 함께 기록한다.

## 5. 특화구역 및 중첩 규제

### 5.1 특화구역별 자료 연결

| 구분 | 함께 연결할 자료 | 초기검토 항목 |
| --- | --- | --- |
| 경제자유구역 | 「경제자유구역의 지정 및 운영에 관한 특별법」, 지정·변경 고시, 개발계획·실시계획 | 해당 지구의 경계, 토지 이용과 입주 관련 조건 |
| 연구개발특구 | 「연구개발특구의 육성에 관한 특별법」, 지정 고시, 관련 계획·관리 자료 | 특구 내 위치와 세부 지구, 토지·건축물 이용 관련 조건 |
| 산업단지 | 산업입지·산업집적 관련 법령, 개발계획·실시계획, 관리기본계획 | 단지 경계, 구역별 용도, 입주 업종·시설 관련 조건 |
| 지구단위계획구역 | 국토계획법령, 결정·변경 고시, 지구단위계획 도서·도면 | 획지별 용도, 건축물 규모·배치 등 해당 계획의 내용 |
| 보전·보호 관련 구역 | 개발제한구역, 농지·산지, 문화유산·자연유산 등 관련 법령과 지정 자료 | 구역별 행위 제한, 추가 허가·협의 검토 사항 |

이 표는 연결할 자료의 유형을 제시한 것이다. 모든 특화구역의 원문·계획을 수집하거나 규정을 추출한 결과는 아니다. 산업단지 관련 법령의 역할은 [한국산업단지공단 안내](https://www.factoryon.go.kr/frtbl/guide2.do), 계획·규제 자료의 접근 경로는 [토지이음](https://www.eum.go.kr/web/am/amMain.jsp)을 참고한다.

### 5.2 대구·경북의 공식 자료 확인 사례

**대구경북경제자유구역:** 공식 소개에서 대구 테크노폴리스지구, 경북 영천하이테크파크지구, 포항융합기술산업지구 등 복수 지구를 확인하였다. 이는 지구명과 소개 자료의 확인이며, 대구·경북 전체가 경제자유구역에 속한다는 뜻이 아니다. 소개 페이지의 면적·사업기간을 최신 법정 경계의 검증값으로 사용하지 않는다. [경제자유구역기획단 공식 소개](https://www.fez.go.kr/portal/dgfez.do)

**대구연구개발특구:** 과학기술정보통신부 고시 제2025-59호, 2025-12-04의 「대구연구개발특구 지정 고시 일부개정」을 확인하였다. 해당 게시물에는 지정 변경 내용과 지형도면, 토지의 지번·지목 현황 첨부 목록이 있다. 고시의 존재와 게시 본문을 확인했으며, 첨부 도면의 필지별 대조와 기준일까지의 후속 변경 전수 확인은 수행하지 않았다. [토지이음 고시 원문 게시물](https://www.eum.go.kr/web/gs/gv/gvGosiDet.jsp?seq=624539)

경제자유구역, 연구개발특구, 산업단지, 지구단위계획은 각각 별도 기록으로 둔다. 같은 이름의 개발사업이 여러 자료에 등장하더라도 공간 경계와 적용 조건이 모두 같다고 추정하지 않는다. 특구 명칭만으로 규제 면제나 다른 규정의 적용 배제를 자동 판정하지 않는다.

## 6. 초기검토 자료의 정리 흐름

1. **대상지 입력:** 소재지, 필지 식별정보, 면적, 실제 이용 상태와 예정 용도를 기록한다.
2. **기초 자료 확인:** 토지이용계획, 지적·건축 관련 자료 등 확인에 사용한 자료와 기준일을 기록한다.
3. **국가 법규 선별:** 토지·행위·용도에 따라 관련 법률과 하위 법령을 연결한다.
4. **지역 조례 연결:** 법령의 위임 대상과 실제 소재지를 기준으로 적용 후보 조례를 연결한다.
5. **구역·계획 대조:** 지정 고시와 도면, 개별 계획에 포함되는지 확인한다.
6. **검토 항목 정리:** 적용 후보, 확인된 근거, 미확인 조건, 추가 대조 항목을 나눈다.
7. **검토 기록 보관:** 출처, 버전, 확인일과 검토 결과를 함께 저장한다.

이는 제안하는 자료 정리 흐름이며, 자동 분석 기능의 구현 상태를 설명한 것이 아니다. [토지이음](https://www.eum.go.kr/web/am/amMain.jsp)은 토지이용계획·도시계획·고시정보의 열람 경로이고, 공식 확인서 발급 경로는 [정부24 토지이용계획확인신청](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=15000000013&HighCtgCD=A09005)에서 확인할 수 있다.

## 7. 개발 참고용 JSON 자료

### 7.1 실제 자료와 예시의 구분

아래 JSON은 **이 문서에서 새로 작성한 구조 설명용 예시**이다. 기존 프로젝트의 실제 데이터베이스나 실제 필지의 검토 결과를 내보낸 것이 아니다. 예시 1의 법령명·시행일·공포번호는 열람한 공식 표제 정보이고, 나머지 식별자·분류·저장 구조는 개발용 예시이다.

| 필드 | 의미와 기록 원칙 |
| --- | --- |
| `record_id` | 자료를 구분하는 내부 식별자. 공식 법령번호와 구분 |
| `is_example` | 설명용 예시 여부. 아래 예시는 모두 `true` |
| `source_type` | `law`, `decree`, `rule`, `ordinance`, `notice`, `plan` 등 자료 유형 |
| `official_title` | 공식 제명. 약칭과 구분 |
| `jurisdiction` | 적용 범위를 검토하기 위한 관할 정보 |
| `legal_version` | 공포번호, 공포일, 시행일 등 열람 버전의 식별정보 |
| `article_reference` | 조·항·호·별표 등 세부 근거. 미확인 시 `null` |
| `source` | 원문 링크와 실제 접근일 |
| `verification` | 출처·본문 대조·현행성 확인 상태를 각각 기록 |
| `application_review` | 특정 필지에 적용하는 검토의 진행 상태 |

### 7.2 예시 1: 법령 참고자료 레코드

국토계획법의 공식 표제에서 확인한 정보는 [국가법령정보센터](https://www.law.go.kr/LSW/lsInfoP.do?lsId=009294)를 근거로 한다. 본문 조문을 추출·검증한 레코드는 아니다.

```json
{
  "record_id": "EXAMPLE-LAW-001",
  "is_example": true,
  "source_type": "law",
  "official_title": "국토의 계획 및 이용에 관한 법률",
  "jurisdiction": {
    "scope": "전국",
    "project_regions": ["대구광역시", "경상북도"]
  },
  "legal_version": {
    "promulgation_number": "법률 제21447호",
    "promulgation_date": "2026-03-05",
    "effective_date": "2026-07-01"
  },
  "review_topics": ["용도지역", "개발행위", "지구단위계획"],
  "article_reference": null,
  "extracted_rule_text": null,
  "regulatory_values": null,
  "linked_records": [],
  "source": {
    "url": "https://www.law.go.kr/LSW/lsInfoP.do?lsId=009294",
    "accessed_on": "2026-11-05"
  },
  "verification": {
    "source_access": "confirmed",
    "version_header": "confirmed",
    "text_match": "not_checked",
    "current_version": "needs_review",
    "current_version_checked_on": null,
    "note": "제명과 열람 버전의 표제 정보를 확인했습니다. 조문·부칙 전체의 현행성 검증은 수행하지 않았습니다."
  }
}
```

`project_regions`는 이 프로젝트의 관심 지역이다. 법률 자체가 대구·경북에만 적용된다는 뜻이 아니다. `linked_records`는 현재 연결해 둔 자료의 목록이며, 빈 배열이 관련 법령이나 조례가 없다는 뜻은 아니다.

### 7.3 예시 2: 필지별 검토 기록

아래의 “예시 필지 A”는 실제 필지가 아니다. 주소·필지번호·수치와 구역 지정 여부를 임의로 채우지 않았다.

```json
  "parcel_label": "예시 필지 A",

  "parcel": {
    "province_or_metropolitan_city": "대구광역시",
    "city_county_district": null,
    "address": null,
    "parcel_identifier": null,
    "area_square_meters": null,
    "land_category": null,
    "actual_use": null
  },
  "proposed_use": null,
  "land_use_designations": null,
  "special_zone_memberships": null,
  "candidate_rule_ids": ["EXAMPLE-LAW-001"],
  "linked_ordinance_ids": [],
  "linked_notice_ids": [],
  "application_review": {
    "status": "not_started",
    "applicable_rule_ids": null,
    "building_coverage_ratio_percent": null,
    "floor_area_ratio_percent": null,
    "conclusion": null,
    "reason": "실제 필지와 사업 내용이 입력되지 않아 적용 규정과 활용 가능 여부를 판단하지 않았습니다."
  }
}
```

### 7.4 상태값과 값 누락의 의미

| 항목 | 상태값 | 의미 |
| --- | --- | --- |
| 출처·표제·본문·현행성 확인 | `not_checked` | 해당 확인을 수행하지 않음 |
| 출처·표제·본문·현행성 확인 | `confirmed` | 이름 붙인 확인 항목만 확인함 |
| 출처·표제·본문·현행성 확인 | `needs_review` | 자료 부족, 불일치 또는 추가 대조가 필요함 |
| 필지 적용 검토 | `not_started` | 검토를 시작하지 않음 |
| 필지 적용 검토 | `in_progress` | 관련 자료를 대조 중임 |
| 필지 적용 검토 | `reviewed` | 근거와 미해결 항목을 기록해 검토함. 인허가 승인과는 별개 |

- `null`은 미입력 또는 미확인이다. 규제 없음, 비적용, 허용 또는 숫자 0으로 해석하지 않는다.
- 연결 목록의 `[]`는 현재 연결한 기록이 없다는 뜻이다. 관계가 전혀 없다는 조사 결과가 아니다.
- 특정 구역의 해당 여부를 확인하지 않았다면 `special_zone_memberships`는 `null`로 둔다.
- 공식 페이지에 접속한 날과 해당 조문의 현행성을 검증한 날은 별도로 기록한다.
- 모든 항목을 한 번에 의미하는 `verified: true` 같은 단일 값으로 검증 상태를 표현하지 않는다.

## 8. 파일 저장 체계 예시

아래는 **관리 구조의 예시**이다. 기존 프로젝트에 이 디렉터리와 파일이 이미 만들어져 있다는 뜻이 아니다. 원본 자료, 가공 자료, 예시, 검토 결과를 구분하는 데 목적이 있다.

```text
land-review-reference/
  README.md
  docs/
    법규_자료_정리.md
    데이터_항목_정의.md
    출처_및_검토기록.md
  references/
    national/
    local/
    notices_and_plans/
  data/
    national/
      laws/
      enforcement_decrees/
      enforcement_rules/
    local/
      daegu/
        metropolitan/
        districts_and_counties/
      gyeongbuk/
        province/
        cities_and_counties/
    special_zones/
      economic_free_zones/
      research_development_zones/
      industrial_complexes/
      district_unit_plans/
    parcel_reviews/
  examples/
    rule_reference.example.json
    parcel_review.example.json
  schemas/
    rule_reference.schema.json
    parcel_review.schema.json
  logs/
    source_checks.csv
    revision_history.md
```

| 저장 위치 | 보관할 내용 |
| --- | --- |
| `references/` | 확보한 공식 원문·고시·도면 등의 보관 사본과 출처 정보 |
| `data/national/` | 국가 법률, 시행령, 시행규칙을 구분한 가공 자료 |
| `data/local/` | 대구와 경북, 광역과 기초 지자체를 구분한 조례 자료 |
| `data/special_zones/` | 구역 식별정보, 근거 법령, 지정 고시·계획·경계 자료의 연결 정보 |
| `data/parcel_reviews/` | 실제 필지별 입력 정보와 적용 검토 기록 |
| `examples/` | 실제 데이터와 분리한 설명·개발용 예시 |
| `schemas/` | 필수 필드, 자료형, 상태값 등을 정의하는 형식 규칙 |
| `logs/` | 출처 확인일, 변경 사항 및 검토 이력 |

파일명에는 자료 종류, 관할, 식별자, 시행일을 구분해 넣을 수 있다. 예를 들어 `law_009294_eff-2026-07-01.json`은 명명 방식의 예시이다. 시행일이 확인되지 않은 경우 임의의 날짜를 넣지 않으며, 다운로드 날짜를 시행일로 대신하지 않는다.

특화구역 자료에는 여러 법령·조례·계획을 연결할 수 있도록 한다. 파일명만 보고 최신 버전으로 판단하지 않고 내부의 시행일·출처·검토 기록을 확인한다. 현재 작업 공간의 동기화된 `sources/` 자료는 읽기 전용으로 유지하며, 이 Markdown 산출물은 그 바깥에 저장한다.

## 9. 실제 확인 범위와 공식 출처

### 9.1 이번 작업의 검증 기록

| 대상 | 실제 수행한 확인 | 수행하지 않은 확인 |
| --- | --- | --- |
| 이전 대화 | 불러올 수 있는 메시지에서 문서 범위와 표현 취지 확인 | 인포그래픽 원본 전체·기존 JSON 파일과의 대조 |
| 국가 법령 | 대표 법령의 공식 페이지, 일부 표제·조문·안내 확인 | 후보 법령의 전 조문·별표·부칙 검증, 적용 법령 전수 확정 |
| 지자체 조례 | 4.2절에 명시한 제명·버전 표제 확인 | 대구·경북 전체 조례 수집, 건폐율·용적률 등 수치 검증 |
| 경제자유구역 | 공식 소개에 나타난 지구 확인 | 특정 필지 경계, 최신 개발계획·허용 업종 대조 |
| 연구개발특구 | 지정 변경 고시의 게시 본문과 첨부 목록 확인 | 첨부 도면의 공간 분석, 후속 변경 전수 확인 |
| JSON | 이 문서의 구조 예시 작성 | 기존 프로젝트 데이터와의 일치, 실제 서비스 연동·자동판정 검증 |
| 개별 토지 | 실제 대상 필지 미제공 | 활용 가능 여부, 인허가, 규제 수치와 사업성 판단 |

출처 확인은 법적 적용 검증과 다르다. 특히 법령 페이지의 제명 링크는 열람 시점에 따라 다른 버전을 보여줄 수 있으므로, 실제 자료를 저장할 때에는 조문·부칙과 버전 식별정보를 함께 보관해야 한다.

## 10. 표현 및 오탈자 정리 원칙

- 중복 음절과 잘못 반복된 단어를 정리하고, `선별`, `필터링`, `선별·분류` 등 정상 표기로 통일하였다.
- 법령명과 조례명은 가능한 한 공식 제명을 사용하고, 설명에 쓰는 약칭과 구분하였다.
- 깨진 문자, 의미 없는 장식 기호와 불필요한 아이콘을 제외하고 표·목록·코드 블록으로 구성하였다.
- `구조화 완료`, `검증 완료`, `자동 분석 완료`처럼 실제 확인 범위를 넘어서는 표현은 사용하지 않았다.
- 진행 수준은 `개발 참고용 법규 자료를 선별·분류하고 일부 JSON 형태로 정리한 단계`라는 이전 대화의 설명에 맞추었다.
- JSON 예시, 파일 체계 예시와 실제 공식 출처에서 확인한 정보를 구분하였다.

이 문서는 대구·경북 토지 활용 초기검토에 필요한 법규 자료를 이해하고 정리하기 위한 개발 참고 문서이며, 실제 검토 결과는 대상 필지와 사업 내용에 관한 근거를 추가한 별도 기록으로 관리한다.
